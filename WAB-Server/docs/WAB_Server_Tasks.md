## 1. Rules for working this backlog

1. **Strict order, one at a time.** `python3 scripts/tasks.py next server` gives the first `TODO` task whose dependencies are `DONE`. **Do not start the next task until the previous task's PR is merged to `server`.** `PENDING` (owner input) and `BLOCKED` (waits on another project's task) rows are skipped; `tasks.py set <ID> DONE` flips `BLOCKED` dependents back to `TODO` automatically.
2. **One task = one branch = one PR.** Branch name is in the table (`feat/srv-NNN-<key>`), created from the freshly fetched `origin/server` (the server master branch; `git branch --no-track feat/... origin/server`); the PR targets `server`. Never commit/push to `main` or `server`; never force-push; never `--no-verify`. *(Exception: SRV-000 — this backlog — was produced on the cloud-session branch `claude/busy-johnson-2rch94`.)*
3. **Status legend:** `TODO` ready to start · `IN PROGRESS` branch open · `IN REVIEW` PR open · `DONE` merged to `server` · `PENDING` waits for **information or an action from the owner** (the *Pending on* column says exactly what) · `BLOCKED` waits for a task of another project named in *Needs* (managed by `scripts/tasks.py`). A task is **never** `PENDING` just because it is large or because a dependency can be stubbed — stub it behind an interface instead (`ROADMAP.md` §2).
4. **Small:** a task should fit in about one working day and touch one module/concern. If it grows, split it into a new row (append `a`, `b`) before coding.
5. **Definition of done (every task, plus `WAB-Server/CLAUDE.md` §10):** unit tests for every acceptance criterion + edge cases, all green · lint/typecheck/build green · no hardcoded values (settings, config, constants, localized messages) · no secrets · Swagger + Postman regenerated (`npm run docs`, `WAB-Server/CLAUDE.md` §11) and committed, or `API docs: no change` noted · **one verification loop (`Loops: 1/1`)** and **4-role review** recorded in `.claude/session.md` · `memory.md` updated with durable facts · PR opened · status here changed (`IN REVIEW` on PR, `DONE` after merge).
6. **Requirements order of precedence:** PRD > `WAB_Backend_BRD.md` > `BUSINESS_DOMAIN.md` (data/rules) > Design Script. Conflicts → stop and ask the owner; do not guess.
7. **Legacy document:** `WAB-Server/BRD.md` (4-digit OTP, Cloudinary, `/v1/customer/...`, role field, express-validator) is **superseded** by the Backend BRD + `BUSINESS_DOMAIN.md` (6-digit Firebase OTP, S3 via `wab-storage`, `/customer/v1`, own JWT with scopes). Do not implement it; it is kept for history only.
8. **Server must stay mock-friendly:** every external dependency (Firebase OTP, S3, FCM/SMTP, payment gateway, BigQuery) is behind an interface with a config-selected fake (Stage C). Real providers are the `PENDING` tasks.
9. **Money** is integer fils (only via `utils/money`); **time** is UTC stored / Asia/Amman computed (only via `utils/time`); **errors** use the codes of `BUSINESS_DOMAIN.md` §11 (if `WAB-Server/CLAUDE.md` examples differ, e.g. `BOOKING_SLOT_TAKEN` vs `SLOT_TAKEN`, the domain list wins); **every response** uses the base envelope of `WAB-Server/CLAUDE.md` §6 and is localized by `Accept-Language` (default `ar`); stored `{ar,en}` content is returned in the requested language to customer/merchant and in both to admin; notifications are localized to the **recipient's saved language**.
9a. **Server rules apply to every task** (`WAB-Server/CLAUDE.md`): read its §0 list first; list the `BUSINESS_DOMAIN.md` sections and BE/NFR ids touched in the task's acceptance criteria; re-read them before pushing (verification loop 1); layered flow route → middleware → controller → service → repository → schema; separate `customer`/`merchant`/`admin` modules with shared logic in `domain/`; no `any`; no hardcoded values (`config/`, `constants/`, `settings`, `locales/`); no duplicated helpers.
10. **Contracts:** the generated `WAB-Server/docs/api/openapi.{common,customer,merchant,admin}.json` + Postman files ARE the contract every client builds against (`INTEGRATION.md` §3). Every endpoint change regenerates them in the same PR (`npm run docs`, `WAB-Server/CLAUDE.md` §11) and names the client tasks affected (admin `api:sync`, customer/merchant DTO regeneration) in the task block.
