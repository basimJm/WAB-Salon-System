`MONGO_URI`, `REDIS_URL`, `JWT_*`/access secrets, `PAYOUT_ENCRYPTION_KEY` (prod required), `*_PROVIDER`, FCM/SMTP/EMAIL keys above, `CORS_ALLOWED_ORIGINS`, `TRUST_PROXY_HOPS`. Full list and defaults: `src/config/env.schema.ts`, `src/constants/env.ts`, `.env.example`.

## Gate

`npm run format:check && npm run lint && npm run typecheck && npm run build && npm test` (no GitHub CI; GitGuardian scans PRs). Docs test must be green. Merge own PR into `server` after the gate.

## Salon branches contract (Stage P, SRV-136…148, 2026-10-26)

Regenerated `docs/api/openapi.{customer,merchant,admin}.json` + Postman. Every change is additive; single-branch salons and older app builds keep working (salon-level endpoints act on the main branch or the member's branch, salon place/hours fields mirror the main branch). Error codes: `BRANCH_NOT_FOUND`, `BRANCH_NOT_BOOKABLE`, `BRANCH_REQUIRED`, `BRANCH_LIMIT_REACHED`, `BRANCH_HAS_UPCOMING_BOOKINGS`, `LAST_BRANCH`, `BRANCH_SCOPE_DENIED`. Setting `salon.maxBranches` (20).

## Contract review against the client PRDs (SRV-128, 2026-10-26)

Customer PRD §13 and Merchant PRD §15 were checked against `openapi.customer.json` (43 paths) and `openapi.merchant.json` (86 paths). Every listed capability has an operation. Gaps found and fixed: merchant eligible staff before a reassign (SRV-128a) and the branch on the customer booking draft (SRV-128b). Not gaps: notification rows carry no branch field (the server writes the text; tapping opens the booking, which shows the branch); analytics go to Firebase, not the server (PRD §14).
