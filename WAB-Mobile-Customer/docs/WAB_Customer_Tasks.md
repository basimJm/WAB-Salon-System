## 1. Status legend
`TODO` ready to start · `IN PROGRESS` branch open · `IN REVIEW` PR open · `DONE` merged to `customer` · `PENDING` waits for **information or an action from the owner** (the *Notes* column names it) · `BLOCKED` waits for a task of another project named in *Needs* (managed by `scripts/tasks.py`).

## 2. Working rules
1. **Strict order, one at a time.** Take the task `tasks.py next customer` gives; do not start the next until the previous PR is merged into `customer`.
2. **One task = one branch = one PR**: `feat/cus-NNN-<key>` from the freshly fetched `origin/customer`; PR targets `customer`; the user merges `customer` into `main`.
3. **Feature recipe (every screen task):** `feature/<name>/domain` (models, repository interface, use cases) → `data` (DTOs generated from `openapi.customer.json`, mappers, Ktor service, repository impl, fixtures for the mock source) → `presentation` (Contract: UiState/UiAction/SideEffect; ViewModel by `mvi(...)`; stateless Screen `(state, onAction)` with previews for loading/content/empty/error, AR RTL + EN LTR, phone portrait/landscape, tablet, font scale 2.0) → `di` (Koin module). Every ViewModel, use case and mapper has a `commonTest`.
4. **Contract = the server OpenAPI.** Never hand-write a response shape; regenerate DTOs (CUS-009) when the server changes and fix the compile errors. A screen that needs data the contract lacks stays `BLOCKED` on a new `SRV-` row (ask the server backlog, Stage N/O).
5. **Done means:** acceptance criteria in `WAB-Mobile-Customer/.claude/session.md`, unit tests green, `scripts/ci/run_local_checks.sh` green, all four Android variants + both iOS schemes build (CI or local), AR + EN strings, no hardcoded values, `Loops: 1/1`, four-role review, `tasks.py set CUS-NNN DONE`, durable facts in `WAB-Mobile-Customer/.claude/memory.md`.
