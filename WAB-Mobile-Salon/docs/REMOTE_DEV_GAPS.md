# Remote dev API — gap list (MER-054)

Dev builds use `DATA_SOURCE=remote` against `DEV_API_BASE_URL` (Android `gradle.properties`) / `API_BASE_URL` (iOS `Dev.xcconfig`), both the hosted dev API (SRV-011a); `scripts/ci/tests/test_dev_remote_config.py` keeps both platforms on `remote` and on the same host. Prod stays `remote`.

How the shapes and the filtering were checked (2026-10-25, same tooling as the customer app, CUS-060):
- `scripts/capture_remote_fixtures.py` (+ `capture_flows.py`, `capture_edits.py`) captured the real envelope of **87 of the 94 operations the app calls** into `core/data/fixtures/remote/<OperationId>.json` (plus 9 related ones: refresh, previews, eligible staff, branch by id). Public, read-only operations come from the hosted dev API (no phone number, token or proof is sent there); everything else from the local real stack (same server code, fake OTP provider) signed in as the demo salon "Lamar Beauty Lounge" (owner, Khalda branch manager, Khalda employee). Mutations ran on throwaway records only (customer + bookings, team member, branch, closure, leave, gallery photo, salon application); settings were written back with the values they had. Tokens and pre-signed URLs are redacted; local media URLs are rewritten to the dev CDN.
- `scripts/contract_gaps.py` compares every captured envelope with its OpenAPI success schema (missing required field, null, wrong type, enum value, undeclared field; `allOf` merged): **0 breaking gaps**, 6 undeclared fields (#9) on contract 1.3.0; **0 gaps** after the 1.4.0 re-sync (MER-068, 2026-10-25).
- `api_sync.py` embeds the captured envelopes in `MockFixtures` (mock mode serves real shapes where no feature fixture overrides them; `MockFixtures.captured` lists them) and generates `ContractDecoders` (commonTest). `ContractFixturesTest` decodes every fixture with the generated DTOs and the app's own `NetworkJson`, checks that every operation the app calls is captured (except #12) and that branch paths decode with the salon-level DTOs the app uses (`branchPath`); each feature has a `Real*Fixture(s)Test` running its mappers on the captured responses.
- Permissions (26 probes, all as expected) and Socket.IO (`scripts/realtime_probe.mjs`: owner, Khalda manager, Khalda employee and another salon's owner listening while bookings were created and answered on the main branch and on Khalda).

Re-capture (local stack running): `python3 scripts/capture_remote_fixtures.py --public-base <dev API> --auth-base <local API> --owner 789000001 --manager 789010001 --employee 789010002` (`--checks-only` = reads + permission / conflict probes, nothing written), then `python3 scripts/contract_gaps.py` and `python3 scripts/api_sync.py`. Socket probe: `node scripts/realtime_probe.mjs <local API> <dir with socket.io-client> <out.jsonl> <seconds> owner=789000001 manager=789010001 employee=789010002`. Both refuse any host but localhost for sign-in.
